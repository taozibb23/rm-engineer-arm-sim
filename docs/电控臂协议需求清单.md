# 给电控 / 组长的机械臂协议需求清单

> 目的：工程机器人（diesel）机械臂要接入视觉闭环，需要一份**臂控制 + 关节反馈**的 RoboLink 协议。
> 现状：现有 RoboLink 只有**云台**帧，**没有任何臂关节 / 夹爪帧**。本清单列出需要电控确认 / 定义的内容。
> 视觉侧已备好占位实现（`arm_sitl/protocol.py`）和软件在环仿真（SITL），协议一定即可联调。
> **这是需求草案，不是已确定协议；编号 / 单位 / 坐标以电控最终登记为准。**

## 1. 为什么现在需要

- 视觉侧已完成：运动学 FK/IK、手眼坐标链、合成相机、抓取任务状态机、SITL 闭环（仿真级）。
- 卡点：**没有臂协议**，视觉算出的关节目标无法下发，也读不到关节反馈，闭环接不上真机。
- 一旦协议确定：改 `arm_sitl/config.json` 的 `protocol` 段 + 对账 `protocol.py`，即可从"纯仿真"切到"半实物 HITL"。

## 2. 现有 RoboLink 可复用的部分（已核对 robolink_v0.1）

| 项 | 现状 | 臂协议沿用 |
|---|---|---|
| 帧头 | 版本 `0x02`、小端、IEEE754 f32 | 沿用 |
| 校验 | CRC-32 / ISO-HDLC | 沿用 |
| 消息号段 | `0x10` 状态类、`0x20` 控制类、`0x21–0x6F` 预留 | 臂控制申请控制类空号、臂反馈申请状态类空号 |
| 能力协商 | HELLO capability bit（如云台轨迹 `0x23` 用 bit35） | 臂帧也需 HELLO 声明 + MCU 实现后才发 |
| 已有控制帧 | `0x20 CONTROL_SNAPSHOT`(48B, 云台)、`0x23 GIMBAL_TRAJECTORY_POINT`(草案) | **不占用、不修改**，臂用新号 |

## 3. 需要定义的两类帧

### 3.1 臂控制帧（PC → MCU）

| 字段 | 类型 | 说明 / 待确认 |
|---|---|---|
| `control_seq` | u32 | 与云台共用控制序号还是独立？**待确认** |
| `stamp_us` | u64 | 指令生成时刻；时钟域 **待确认** |
| `joint_target[3]` | f32×3 | ψ/α/β 目标角。**单位 rad 还是 deg？几何角还是电机角？** 见 §4 |
| `gripper_cmd` | u8 | 0=张开 1=闭合（或力度比例？**待确认夹爪类型**） |
| `flags` | u8 | 使能 / 撤销 / 模式位。**使能语义是否沿用 CONTROL_SNAPSHOT.flags？** |

### 3.2 臂反馈帧（MCU → PC）

| 字段 | 类型 | 说明 / 待确认 |
|---|---|---|
| `seq` | u32 | 对应控制序号 |
| `stamp_us` | u64 | 反馈采样时刻 |
| `joint_actual[3]` | f32×3 | 实际关节角（**编码器角还是几何角？方向？**） |
| `gripper_state` | u8 | 开 / 合 / 夹持中 |
| `status` | u8 | 位标志：moving / attached(夹持确认) / placed / fault。**夹持确认靠什么传感？** |

## 4. 必须确认的关键约定（最容易翻车）

1. **角度域**：视觉算的是**几何角**（相对水平仰角）。下位机电机收的是**编码器角**。
   两者差一个**传动比 + 零偏 + 方向**（皮带 yaw、左右电机大小臂）。
   → 请电控提供传动比 / 零偏 / 方向，或明确"PC 发电机角、映射在 PC 做"还是"PC 发几何角、映射在 MCU 做"。
   **未确认前禁止把几何角当电机角下发。**
2. **单位**：rad 还是 deg（云台历史上 deg→rad 改过，臂要一次性定死）。
3. **坐标系 / 零位**：零 yaw 向前 +x、左 +y、上 +z；正 yaw 逆时针（从上往下）。机械零位在哪、编码器方向是否一致。
4. **限位**：软限位范围（ψ/α/β）、硬限位、超限行为。
5. **安全**：急停硬路径（不依赖中间件）、使能 / 撤销 / 断链降级语义。
6. **时间戳**：谁打、采集时刻还是接收时刻、与相机 / IMU 时钟域关系。
7. **频率 / 配额**：控制帧率、反馈帧率、总线带宽预算（参考云台 1kHz 起步）。
8. **夹爪与装配确认**：夹持成功判据（力 / 位置 / 电流？）、装配成功判据（传感器？）。
   **写串口成功 ≠ 抓住 ≠ 装配成功**，需要明确反馈。

## 5. 视觉侧已准备的占位实现（供电控参考 / 修改）

- `arm_sitl/protocol.py`：占位臂协议，帧格式仿 RoboLink（头+类型+长度+载荷+CRC32）。
  - 占位 `arm_control_msg_type=36 (0x24)`、`arm_feedback_msg_type=20 (0x14)` —— **非正式分配，待登记**。
  - 载荷：`seq u32 | stamp_us u64 | psi/alpha/beta f32×3 | gripper u8 | flags/status u8`（26B）。
  - 角度域当前 `geometric_placeholder`。
- `arm_sitl/config.json` 的 `protocol` / `arm.transmission` 段：协议与传动映射的配置入口。

## 6. 建议验收顺序（对齐战队"验证级别不可向上借"）

1. **字节对账**：离线 encode/decode + CRC 篡改拒绝（视觉侧已有测试）。
2. **禁能联调**：只握手 / 保活 / 读反馈，不发运动（参考云台只读联调）。
3. **使能联调**：电控确认安全后，单关节低速点动 → 多关节 → 抓取。
4. 每步保留版本 / 原始日志 / 一次失败定位。

## 7. 给组长 / 电控的具体问题（可直接转发）

1. 臂控制 / 反馈帧用哪两个 MsgType？是否已在 HELLO 登记 capability bit？
2. 关节目标下发的是**几何角还是电机角**？传动比 / 零偏 / 方向谁负责映射？
3. 角度单位 rad 还是 deg？零位与正方向定义？
4. 夹爪类型（开合 / 力度）？夹持确认靠什么传感？
5. 装配成功如何判定？有无传感器反馈？
6. 软 / 硬限位范围？急停与断链降级行为？
7. 控制 / 反馈帧率与带宽预算？时间戳时钟域？
8. 当前固件板卡 / 供电 / 备份与安全联调条件？
